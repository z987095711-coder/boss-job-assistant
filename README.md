# 社会边角料 v0.2

本地运行的 BOSS 直聘求职助手。基于 v0.1.11 的已跑通投递流程，接通 **投递 → 消息值守 → 新消息回复 → 简历请求处理**。界面名 v0.2，Chrome 清单中的版本号为 0.2.0。

不是云端托管服务，不接管服务器登录，不调用模型接口，不上传个人配置给第三方。经用户在插件中授权的介绍、回复和简历，仍会通过 BOSS 网页发给对应招聘方。首次使用需要用户核实话术、附件和发送范围。

## 原地升级，保留原配置

先暂停旧任务。将本包 **extension 文件夹中的所有文件** 覆盖到原先加载的扩展目录（该目录直接包含 manifest.json），保持原路径，不卸载、不清除数据。在浏览器扩展管理页重新加载，然后刷新所有已打开的 BOSS 职位页与消息页，再重开侧栏，确认显示“社会边角料 v0.2”。无需新增权限。

保留已导入的方向、行业、附件绑定、真实话术、历史投递与去重记录、原牛马小丑图标。旧版本没有“投递后消息值守”设置时，升级会默认开启该设置和防闲置睡眠；启动前可以取消。升级和浏览器重启不会自行开始发送，必须点击开始／继续。未核验的提交保留，不因升级变成重发。

## 最少操作的两条使用路径

### 还需要投递

第三步可点 **“一键打开职位页并绑定”**，自动打开或复用官方职位列表，等待岗位可读后绑定。不再要求先手动打开网址或点击卡片；此按钮只读，不投递。

第五步核对方向、介绍、数量，保留 **“投递结束后立即进入第六步，持续监听并回复”** 的勾选，点击“开始自动沟通”。本批结束后自动打开／复用消息页并进入第六步。目标不足或单岗位失败同样收尾转入消息值守，不会为凑成功数超量投递；验证码、登录失效等明确平台阻断则暂停。

### 已经投完，只需要看消息

直接到第六步，保留 **“持续值守整个消息列表”** 的勾选，点 **“一键开启消息值守”**。会自动加载消息页、读取联系人并点击待处理会话；右侧没有打开任何对话也可开始。不需要重新投递、不需要先手动点联系人。

第六步持续模式不以“单次处理数量”作为总会话上限，也不再只监听首批会话。取消持续值守后，保留原来的有限数量两轮模式：首轮介绍／答题，第二轮可按附件设置主动申请发简历，然后结束。不要把这个可选旧模式与默认的仅待答消息值守混淆。

## v0.2 的实际行为

### 职位页入口

新建职位页使用 `https://www.zhipin.com/web/geek/jobs?ka=header-jobs`。已有正确职位页优先复用，保留其筛选 URL；不把在线简历页或无关页面改成岗位页。需要重新绑定时先暂停任务。

### 消息值守

消息页变化由只读 MutationObserver 检测，250 毫秒合并 DOM 变化；同时有页面 5 秒读状态／心跳和后台 30 秒恢复闹钟作为补充。不是反复刷新网页，不拦截网站私有接口，不模拟在线身份。Chrome 的后台调度、网页推送、网络和当前操作会影响延迟，**不是硬实时、不是保证秒回**。

队列依次优先未读、明确对方最后发言／已读未答，再处理其他会话的首次只读核验。每次启动会核验已有会话，避免“我发过介绍但 HR 的简历请求卡片仍未处理”被漏掉。最后一句是自己发的普通等待会话只读取、不催促、不主动发附件。发送前重新读取双方消息和当前会话身份；已手动回答、已发送、未核验提交和不同的手工草稿都有保护。

持续扫描期间可以发现新出现的联系人；没有新消息就等待。为避免异常网页无限滚动，每轮列表扫描有 60 页上限；触及时会在状态面板标明，较早的会话可能未覆盖。一次扫描完成后回到列表顶部，30 秒后安排下一轮完整列表核验；新 DOM 变化不必等这一轮结束才入队。

面板显示：是否运行、最近检查时间、队列长度、当前步骤、防闲置睡眠状态以及需要人工处理的会话。界面的“最近检查”是插件读页面的时间，不是网站服务器保证推送正常的证明。

### 同意简历请求并发送第一份

只在**当前会话中具有明确简历含义的请求卡片或底部提示条**寻找“同意”。点击后若出现文件选择框，等待列表稳定、选择当前排列第一份、验证选中、点击该弹窗内的“发送”，最后核验结果。不会因为存在电话／微信交换的“同意”按钮就去点击它。

第一份指发送当时弹窗中的第一项，不是导入列表顺序、不猜“AI／艺术／行研”对应文件。严格绑定选项继续保留，选用严格绑定时仍按绑定文件核对；默认第一份模式不使用该绑定。

网站某些布局若点击同意便直接发送其默认附件，插件只能记录实际结果为“网站默认附件”，不能声称自己选择了第一份，也不会再发送第二份。已收到明确附件回执不重复发送。出现新问题、对方撤销请求／要求停止、收件人变化或文件排序改变时不按旧计划提交。不能确认是否已经提交则待核验，不盲目重试。

### 拒绝关键词与一次原因追问

规则识别“抱歉／对不起／不符合／不合适／不匹配”等，但结合否定、疑问和拒绝句式，不把“抱歉刚看到”当作拒绝。只有道歉词而没有足够上下文时交人工处理。

普通拒绝使用第六步可编辑的已确认话术，最多礼貌追问一次主要不匹配的原因；保留历史介绍去重。已追问过不再追问，不自动降低薪资、不承诺未确认技能／客户／业绩、不用连发消息施压。对方明确说不要联系、不要打扰、停止沟通则不再发送。关键词规则不是通用语言模型，对含糊或复杂语义仍可能无法准确判别，需要用户审查。

两条 48／72 小时跟进仍默认关闭，与一次拒绝原因追问分开。持续值守不会自行打开或执行定时催促。

## 运行条件与暂停

保持电脑开机联网、浏览器运行、BOSS 登录有效。默认仅在实际运行期间申请 `chrome.power.requestKeepAwake('system')` 防止因闲置进入系统睡眠；允许屏幕熄灭，不修改永久电源方案。工作消息页运行期间暂设为不可自动丢弃，暂停后恢复原属性。发生页冻结／被丢弃时尝试唤回该页，可能将它切到前台；这不是阻止所有浏览器冻结的保证。

手动关机、强制休眠、合盖策略、网络断开、浏览器退出、账号掉线都不等于“云端继续工作”。浏览器重启后需要继续／重新授权。消息页意外关闭且没有正在提交的动作时可自动重新连接；有未核验提交时暂停留待核验。登录、验证码、额度限制不绕过。

你在聊天输入框输入或主动点击联系人时，人工优先，机器人暂停。使用其他软件或切到别的非聊天页面不作为发送指令。所有暂停、阻断都释放运行中的防睡眠请求。第六步“暂停回复”或第五步“全部暂停”可以停止值守，已提交到网站的动作无法撤回。

## 边界与隐私

本版没有云端服务。云端并非技术上绝对不可做，但需要单独解决账号授权、持续浏览器环境、数据保护和平台许可；本地插件也不等于自动获得平台合规许可。本项目没有核验或取得 BOSS 对该自动化产品的专门授权，不宣称规避风控、封号风险为零或官方认可。

只发送用户审核的话术及已上传网站的简历；缺失资料留空并进入待人工队列，不捏造学历、任职、客户、成绩。插件不获取 Cookie、验证码或银行信息。个人配置和执行状态存于本地；自行导出配置仍可能包含真实求职资料，应保密。默认诊断不含完整聊天、附件正文和话术正文；手动勾选导出话术时要自行检查。

## 测试与源码

`docs/TEST_REPORT.md` 是本版实际测试记录及限制；`tests/` 提供纯逻辑／后台模拟测试、Chromium 合成页面测试和原生加载尝试脚本。本环境未能加载原生 MV3 扩展，未登录真实账号、未实投、未整夜值守，也未完成真实系统睡眠测试。合成测试通过不代替真实页面兼容性验证。

本地复验：安装 Node 后运行 `npm test` 与 `npm run check`。浏览器测试需 Python、Playwright 和 Chromium，脚本中的 Chromium 路径按本机修改；这些测试不访问真实账号。主要入口：`tests/v02_browser_test.py`、`tests/v010_browser_test.py`、`tests/v011_browser_test.py`。较早的其他 Python 测试留作历史工具，不列入本版验证结论。

架构：`core.js` 规则与队列；`adapter.js` DOM 识别和带守卫的操作；`content.js` 只读观察与动作桥接；`background.mjs` 单一执行器、日志、持久化与状态转换；`robot.js` 消息值守；`panel.*` 控制面板。六步间共享同一个后台执行器，不并发抢同一聊天。

技术资料：Chrome 官方 power、alarms、tabs 及 extension service worker lifecycle 文档。参见 `docs/DEVELOPMENT.md` 中的具体引用。
